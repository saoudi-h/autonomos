# [PROTO-17] Fix migration gaps found by PROTO-16 round 1

## Outcome

Protocol 0.8.1-alpha. Five agents migrated postdot, commerce, infra, agency and sandy with 0.8.0: every mechanical criterion passed (IDs, links, dry-run first, worklog shape, `close`), so the fixes target the tool, not agent behaviour:

- `migrate` moves top-level checked items without a `**[ID]**` tag (postdot: 48, infra: 5 were moved by hand).
- `migrate` lists closed records that still mention unfinished work (unchecked items, follow-up wording).
- Git-ignored worklogs stay ignored after the move (`archive/worklogs-format-1/.gitignore`); infra nearly committed 84 private worklogs.
- Rerunning `migrate` after merging quarantines legacy worklogs dated before the quarantine (ignored files of another checkout).
- `close` groups same-day closures under `Closed <date>` instead of the last migration batch heading.
- `update` only bumps an existing `@autonomos/cli` pin; it no longer adds one.
- Workflows: use the project's own CLI install; a delegated or explicit request authorizes the stated plan.

## Decisions

- Untagged checkboxes count only at top level; inside an entry they are criteria or evidence.
- Quarantine date is read from the archive index, so no manifest field was added.
- Protocol version bumped because `PROTOCOL.md` changed (`update` skips same-version content).

## Validation

core 132 and CLI 35 tests, typecheck, lint. postdot copy: 425 tasks closed (was 377), 52 follow-ups listed.
