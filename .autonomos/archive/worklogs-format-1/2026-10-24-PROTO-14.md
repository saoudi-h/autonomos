# PROTO-14 — Archival and bounded current context

## Authorization and accepted scope

The owner accepted the archival proposal after exploratory cross-model tests and
authorized implementation. SPEC-003 records that acceptance. Implement the
protocol and supporting CLI, prepare a coordinated release, preserve consumer
projects, and do not publish remotely or perform broad artifact cleanup.

## Result

- Protocol v0.7.0-alpha defines claim-level consolidation, scope/acceptance-based
  eligibility, preserved current knowledge, batch archives, searchable IDs/topics,
  intact historical records with repaired references, new completion dates and
  explicit preservation of unknown old dates. No cleanup workflow, Sprint object,
  calendar job or automatic semantic archiver was introduced.
- Reconcile investigates and archives; crystallize replaces current knowledge
  instead of appending journals. Session avoids archives at bootstrap. Task/issue
  workflows reserve identifiers against current and archived records. Optional
  Current direction belongs in the task registry, not a new mandatory document.
- Core exports `ARCHIVE_DIR`, `TaskParser.references` and `readTaskRegistry`.
  References include source path/line, recognize metadata-free legacy IDs and
  skip fenced examples. History is opt-in and scans archive TASKS.md files only;
  collisions, skipped links and failed reads remain explicit. The detailed
  `TaskParser.parse` API is unchanged.
- CLI `status --history` separates current/historical counts. Historical status
  is not current work or proof of completion. Incomplete reads and duplicate IDs
  produce diagnostics and exit code 1. Default status does not inspect archives.
- Init/update behavior remains non-destructive. Tests now cover archive index,
  task/issue records and worklog byte preservation and absence of empty archives.
- Public-safe evaluation summary and a repeatable fictional fixture are retained
  under docs/research. Raw private cross-project results were not imported.
- A minor changeset for Core and CLI prepares their coordinated 0.7 release.
  Package manifests remain 0.6.0 until the normal Changesets versioning step;
  published workspace resolution pins the matching exact Core version.

## Review and corrections

An independent Luna-max implementation review found that a linked `.autonomos`
ancestor bypassed the archive no-follow checks. Core now rejects it before task
reads, and CLI rejects it before manifest reads; two regressions cover this.
Direct archive/file links are also skipped with incomplete-read diagnostics.
This is a normal filesystem traversal policy, not a hostile concurrent-filesystem
sandbox guarantee.

A separate Sonnet-medium read-only exercise using the actual kernel/workflows
preserved the unimplemented accepted spec, active publication block, valid mixed
subclaims and open parent acceptance. Its proposed AGENT.md contained no task or
incident narrative. Some suggestions still required human judgment (batch scope
and speculative uncertainties); this is evidence of clarity, not a reliability
guarantee or a replacement for source verification.

## Boundaries and next step

No consumer repository was modified, no installed consumer protocol was edited,
and no remote push, release or publication occurred. The upstream repository's
installed workflows remain on their existing release; managed copies change only
through the versioned update path. Existing historical task entries were left
unchanged. No root AGENT.md entry was needed because the new rules belong in the
protocol itself.

Recommended next task: version and publish the coordinated Core/CLI release,
then update a chosen consumer and run a bounded real `/reconcile` archival batch.
